11 / 19
A · 두뇌

copilot-instructions.md

팀의 모든 컨텍스트를 한 파일에.

  • 우리 팀이 누구인지, 무슨 일을 하는지, 어떤 용어를 쓰는지
  • Sean이 응답할 때 지켜야 할 톤, 출력 규칙, 거절해야 할 것
  • 자주 참조하는 폴더 위치, JSON 스키마, 워크플로우
프로그래밍이 아니라, 새로 온 팀원에게 사무실을 안내하는 느낌으로 씁니다.
"이 자료는 어디 있고, 이건 누구한테 물어보고, 식당은 저쪽이고…"
그렇게 자연어로 약 500줄. 한 번 잘 써두면 5명 모두에게 같은 Sean이 응답합니다.
12 / 19
B · 단축키

prompts/

한 번 만들면 5명이 /명령어로 바로 호출.

  • 주간보고 작성, 회의록 정리, 메일 초안 등 반복 작업을 단축
  • 프롬프트 자체를 쓰는 건 어렵지 않음. 어려운 건 "어떤 프롬프트를 만들지 떠올리는 것"
예: /grill-me — 얼마 전 알게 된 프롬프트.
"AI가 나한테 질릴 때까지 질문하게 한다"는 컨셉인데,
어떤 일을 시작할 때 빠진 게 없는지 끝까지 물어봐줍니다.
→ 프롬프트의 가치는 기술이 아니라 이런 컨셉을 발견하는 것에 있습니다.
13 / 19
C · 도구함

skills/

필요할 때만 꺼내 쓰는 전문 매뉴얼+도구 묶음.

  • frontend-design — 슬라이드 같은 HTML 생성 (이 발표 슬라이드도 이걸로 만든 겁니다)
  • agent-browser — AI가 직접 브라우저를 조작
agent-browser — 사내 업무는 브라우저로 데이터 입력/다운로드하는 게 정말 많음.
이걸 AI가 직접 하게 되니 가능성이 확 열립니다.

⚠️ …근데 사실 이거 회사 IT에 승인 안 받고 몰래 쓰고 있습니다. 보안적으로 문제 없는 내부 사이트에서만 쓰고 있어요. 혼내지 마세요 🙏

잠깐 · VS Code의 Agent 모드

Copilot의 Agent는 손이 많습니다.

  • Ask / Plan 모드 — 답변과 계획만
  • Agent 모드 — 파일 생성·수정, 터미널 실행, 코드 검색 등
    다양한 도구를 직접 사용
다만 한계가 있습니다 —
이메일 발송, Teams 메시지, 외부 시스템 데이터 업데이트…
"외부와 소통하는 액션"은 여기서 못 합니다.

→ 그래서 방법을 고안해냈습니다.

VS Code Copilot 채팅 우하단의 모드 선택
→ Agent 선택 시, 도구를 직접 호출
